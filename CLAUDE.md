# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository Layout

This is a Go workspace (`go.work`) containing **seven modules**, each with its own `go.mod`:

- `.` (root, `github.com/go-sphere/httpx`) — framework-agnostic interfaces (`Context`, `Engine`, `Router`, `Binder`, `Responder`, `Error`) plus helpers like `FixWildcardPathIfNeed` and `Start`/`Close`. The root module has **no third-party dependencies** — keep it that way. It also has no response-envelope wrapper: `WithJson` and the `H` map lived here until v0.0.5 and were removed, because an envelope is a convention rather than part of the transport contract and the root copy had drifted from the one callers use (`sphere/server/httpz.WithJson`, which honors a handler-set status, routes 204/304 through `NoContent`, and returns a named `DataResponse[T]`). `ListenAndAutoShutdown` went in the same release, unreferenced anywhere in any of the four repositories.
- `ginx/`, `fiberx/`, `echox/`, `hertzx/` — adapter modules that implement the root interfaces over Gin, Fiber v3, Echo v4, and Hertz respectively. Each is independently versioned.
- `stdx/` — the adapter over plain `net/http`. No framework dependency (only `go-playground/form`, its form/query/uri/header decoder), so `Static`/`HandleStd`/`AdaptStdMiddleware`/`TestRequester` need no bridging and the `Engine` is itself an `http.Handler`. Its router (`stdx/mux.go`, ~200 lines) is the only routing in this repository not inherited from a framework: segment tree, static > parameter > wildcard with backtracking, allocation-free matching, and deliberately **none** of `ServeMux`'s trailing-slash redirects, path cleaning or case fixups — those would put it at odds with the other four. Middleware is composed into the route at registration on every adapter now, so the cost difference this bullet used to record is gone: 10 layers ≈ 35 ns at 0 allocations here, 47 ns on ginx, 66 ns on echox, 93 ns on fiberx, 304 ns on hertzx — the spread is the frameworks' own per-request cost, not the chain. Two things guard the hand-written part: `stdx/mux_test.go` pins the matching rules and the zero-allocation property, and `conformance/router_differential_test.go` replays random route tables and paths through all five adapters, asserting stdx never contradicts a **unanimous** framework answer (the four frameworks disagree with each other on ~25% of overlapping cases, which is why the bar is consensus rather than "equal gin"; it caught a real wildcard-priority bug on the first run).
- `httpxtest/` — the shared conformance suite (part of the root module, stdlib-only). An adapter supplies a `Suite` (name, `Caps`, an engine factory, and two optional hooks: `StdMiddleware` for `AdaptStdMiddleware` and `NativeMiddleware`, which registers the framework's own middleware through the adapter's `UseNative` — both are needed because neither is reachable through the `Router` interface; stdx leaves `NativeMiddleware` nil, because net/http has no middleware type but the one `AdaptStdMiddleware` takes) and calls `httpxtest.Run`. Case groups: `Middleware`/`Router`/`Static` (registration), `GroupPrefix` (every spelling of a group prefix — `""`, `"/"`, `"/api"`, `"/api/"` — nested combinations of them, an empty or `"/"` route path on each, and `Static`/`StaticFS`/`HandleStd` mounted on each, asserting the route is reachable at `path.Join(prefix, routePath)` and that `BasePath()`/`FullPath()` agree; it exists because the suite used to call only `Group("")`, the one shape that cannot expose a prefix-join bug, and echox therefore 404'd every `Group("/")` route for four releases), `Chain` (registration order, layers nesting inside native middleware on the same scope, depth over nested groups, stopping by not calling `next`, errors joining on the way out and surfacing where the chain was composed), `MiddlewareScope` (which scope's chain covers which requests: engine covers unmatched paths, a group never does, an engine layer may answer a 404, a swallowed 404 keeps its status, late engine registration reaches an existing group, a registered route keeps its chain, `Group`'s variadic), `Auth` (a token-guarded route: golden contracts for the 401 and 403 bodies and for the allowed response, plus counts proving a denied request never ran the handler and that an auth layer on one group does not cover a sibling's public route, and the principal the layer stored reaching the handler on the allowed request), `Recovery` (a panic below a recovery layer — in the route handler or in another layer, on the same scope or an inner group's — unwinds to that layer rather than the framework, its value does not reach the body, the layers outside resume with the classified 500 or with nil when the layer answered the request itself, and the engine still serves the next request), `Observe` (what a layer sees when it reads the response after `next` returns, which is not what the client gets: an error is rendered at the route once the chain has unwound, so `StatusCode()` still reports the framework's default 200 for a request that will answer 403 and only `ClassifyError` on `next`'s error names the real status; a handler that wrote before failing leaves the committed status, and the error can no longer change the response; and a layer that logs an error and returns nil turns a 403 into an empty 200, pinned so all five agree on that footgun rather than one inventing a status), `Commit` (net/http's post-commit rules and `Committed`: the status frozen at the committing write, a later `Status` ignored and not reported by `StatusCode` either, a later `SetHeader`/`SetCookie`/`Content-Type` dropped, a second body appended, a bodyless call changing nothing, and a post-commit write returning nil — plus the read the downstream recover layer makes, with the two-document response it emits ungated and the one it emits gated on `Committed`), `RequestID` (the correlation middleware shape: a supplied `X-Request-ID` is kept and a missing one minted, the ID reaches the handler through both the state store and the standard context, and it comes back on the response header — including on an error response the handler never saw), `Selector` (a layer deciding from `FullPath()`: the pattern carries the group prefixes, a wildcard route is one pattern for every path under it, and an unmatched path or rejected method reports no pattern at all, so a selector can tell "unlisted route" from "no route" — the last two caught fiberx reporting `"/"` for an unmatched path and echox reporting the path-matching route's pattern for a 405, both fixed in the adapter), `ContextBoundary` (a `SetContext` value set below stays visible to the layers above after `next` returns, and crosses into a `HandleStd`-mounted net/http handler and into middleware wrapped by `AdaptStdMiddleware`, while a `Set` value does not: the boundary is the standard context, and the value the mounted handler reads is the one the layer above set), `Caps` (each capability claim is verified against actual behavior, so `Caps` cannot drift into documentation), `Request` (bodies, five binders, forms, uploads, cookies, request info), `RequestEdges` (repeated query/header keys, unknown-length body, encoded and non-ASCII paths, 1 MiB bodies), `Response`/`Context` (every responder, the hand-written success-envelope wrapper that stands in for `httpz.WithJson`, the standard context and its separation from the state store), `Regression` (cases that exist because an adapter once got them wrong), `Contract` (the *absence* of validation, method-name case, registration-time panics, sniffed content types, state-store nil, plain net/http middleware), `Stream`/`ErrorHandling`, and `Scenarios` (the shared `Scenario` table — declarative method/target/header/body so a benchmark can reuse one request and rewind its body without allocating; the rewind also drops `Request.Form`/`PostForm`/`MultipartForm`, because net/http memoizes a parsed body on the request and without that only the first iteration of `MultipartUpload` would parse while fiber and hertz, whose runners reset their native request, parse every time — the row was comparing parsing against a map lookup, reporting the net/http-backed adapters ~5x faster than they are; `httpxtest.RunBenchmarks` measures the same table, so adding a scenario adds both a contract and a benchmark, and `BenchmarkOnly` marks the ones whose response is too large to record). Chain order is asserted twice on purpose: the handler returns it in the body so the golden makes every adapter agree, and the case states the full sequence inline so regenerating a golden cannot accept a reordering. `Suite.Dispatch` is what makes the shared benchmarks measure the adapter rather than the harness: it drives the framework's own dispatcher with reusable buffers (~20 lines per adapter, in `conformance/httpxtest_suite_test.go`). Without it `RunBenchmarks` falls back to `httpx.TestRequester`, which allocates 20+ objects and a few microseconds per request — 98% of an empty request's measurement. Allocation guards also stay in each adapter's module for the same reason (`ginx/middleware_alloc_test.go`).
- `httpxmock/` — an in-memory `httpx.Context` for unit-testing middleware and handlers, part of the root module, stdlib-only. It exists because the alternative had been reached for seventeen times in `sphere` alone: a struct embedding `httpx.Context` and overriding the two or three methods the test needs, where the embedded nil interface fills out the method set and every method the code under test touches but the test did not anticipate panics on a nil dereference. Every method here has a real body, so an un-exercised corner returns a zero value instead — that is the whole point, and `TestSatisfiesContextWithoutEmbedding` enforces it by rejecting any embedded interface field rather than settling for the interface being satisfied. It is **not** inside `httpxtest`: that is the adapter conformance suite, aimed at adapter authors and liable to become its own module, and a downstream consumer testing its own middleware must not have to depend on it. The Context is also the recorder (`StatusCode`/`Committed`/`Body`/`ResponseHeaders`/`ResponseCookies`/`Result`/`Writes`/`LastJSON`/`FlushOffsets`), not a separate `httptest.ResponseRecorder`-style object, because a middleware only ever receives the Context — anything it can observe about the response it observes there — and every fake it replaces already read its response state off itself. Response semantics are net/http's, measured rather than assumed: status and headers freeze at commit, a later `Status`/`SetHeader` is silently ignored, and later body writes append, so `JSON(200,a)` then `JSON(500,b)` leaves status 200 and both encodings concatenated. All five adapters now do that, so the mock is the sixth implementation of the `Commit` contract rather than a net/http-shaped approximation of it; when this package was written it was three of the five, and fiberx and hertzx answered 500 with the late header (fiberx losing the first body) because their buffered response had not committed while the handler ran. The five `Bind*` methods all return `ErrBindUnsupported` and decode nothing: each adapter binds through its framework's decoder and they disagree on real details, the root module cannot import `go-playground/form` to borrow stdx's without taking on its first third-party dependency, and one binder that works next to four that do not is worse than five that behave alike — a test needing real binding drives a `stdx` engine. The sentinel is deliberately not wrapped by `WrapBindError`, so it classifies 500 and cannot be mistaken for a handler's own 400. `Flusher` and `Streamer` are implemented so `httpx.ServerSentEvents` and the downstream `httpz.WithSSE` are unit-testable, recording flush boundaries (`FlushOffsets`) because an SSE test comparing bodies alone cannot tell a stream from a buffer; `NativeContextProvider` deliberately is not, so `AsNativeContext` correctly reports false. A mock Context is safe for concurrent use — stricter than the adapters, whose contexts are single-goroutine and pooled, and not a claim about them: it is what collapses the three plain/atomic fake pairs (`withFakeContext`/`stressFakeContext` and the two `nextRecorder` pairs) downstream into one type. The package also ships the driver those tests need around the Context: `Handler`, a zero-value-usable recording terminus reporting `Called`/`Calls` with an optional `Fn` for a terminus that writes or fails, and `Run(ctx, next, mw...)`, which composes layers through `httpx.ComposeMiddleware` and returns the outermost error — three lines that had been written four times in `sphere`, twice concretely and twice as a generic over a `nextRecorder` interface that existed only so a plain-bool and an atomic-bool fake could share one driver, which a race-safe `Context` and `Handler` delete outright.
- `conformance/` — what genuinely cannot move into `httpxtest`: the cross-framework benchmark tables (`BenchmarkAdapter`, `BenchmarkFramework`, and `BenchmarkNativeVsHTTPX` — which pairs every shared scenario with a hand-written implementation on the raw framework, because "how you would write this without httpx" cannot be generated from the shared table and has to live next to the framework imports), the five suite definitions (until the root module ships `httpxtest`), engine lifecycle and anything needing a **real listener** (trusted proxies/`ClientIP`, incremental stream delivery, FD leaks — the in-process requesters of fiberx/hertzx report `0.0.0.0` as the peer, so a proxy policy cannot be verified through them), the concurrency stress test, and the cases that assert a specific framework's native context type. It uses `replace` directives to point at the local adapter modules. Gin-only diagnostics live in `ginx/` (`call_depth_benchmark_test.go`, `middleware_depth_benchmark_test.go`, `middleware_chain_benchmark_test.go`, `middleware_model_benchmark_test.go`). The golden machinery now lives only in `httpxtest`. All three cross-framework tables cover **five** frameworks: `BenchmarkAdapter`'s `std` rows and `BenchmarkNativeVsHTTPX`'s `stdx` builder pair stdx against a `net/http` `ServeMux` with hand-written decoding, which is the honest "without httpx" side for the one adapter whose framework is the standard library.
- `benchmarks/` — the benchmark documentation and its generator. `benchmarks/BENCHMARK.md` is the **only** current baseline and is generated, never hand-edited; `make bench-report` (`benchmarks/report.py`) compiles the conformance test binary once and measures every table from that one binary back to back, recording the environment, the Go version, the git revision and the uncommitted-file list next to the numbers. That is the whole point of the script: the per-table targets are for iterating on one table, and two of their runs are two different environments, which is why the seven reports now in `benchmarks/history/` cannot be quoted next to each other or next to `BENCHMARK.md`. They are kept because they record *why the code looks the way it does* — which approach was tried, what it bought, why it was dropped (chain fusion, `Interceptor`) — not because they are current. **Nothing under `benchmarks/results/` or `benchmarks/bin/` is tracked**, and this is not a size judgement: `benchmarks/` has no `go.mod`, so it belongs to the root module, and anything committed there ships in the module zip that every consumer of `github.com/go-sphere/httpx` downloads — every adapter depends on the root module. Benchmark samples do not belong in a library's module zip. The reports carry their own tables, so the conclusions survive without the raw output; re-run locally rather than reaching for another machine's samples, which benchstat cannot meaningfully compare anyway. The generator still writes exclusively into `benchmarks/results/latest/` rather than alongside the older `fusion-*`/`gin-depth-*` data, because a generator sharing that namespace will eventually pick a name an archived report already used and overwrite it — which is how the first round's `environment.json` and `network.json` were destroyed. `benchmarks/network.py` is the fixed-rate Vegeta comparison, invoked by `report.py` and runnable on its own; Vegeta stays a CLI so no load-test dependency enters any `go.mod`.

`go.work` overlays the seven modules for local and GitHub Actions builds. Adapter `go.mod` files must **not** contain `replace` (that would ship in `ginx/vX.Y.Z` and break consumers). `go.work` is gitignored, so CI (`.github/workflows/build.yml`, one `check` job) regenerates it with `make work` (which derives the module list from the Makefile's `GO_MOD_DIRS`) before running anything — without it every adapter resolves `github.com/go-sphere/httpx` from the proxy, where the symbols they use do not exist until the root module is tagged. The Makefile exports `GOWORK` automatically whenever `go.work` is present. CI then runs `make tidy-check` (dependency hygiene per module, `GOWORK=off`), `make build` and `make test` — deliberately no linter toolchain, so no tool release can redden a branch by itself; `make check` (format/vet/golangci-lint/nilaway + `test-race`) and `make verify` remain the local gates. Tags are published per-module as `ginx/vX.Y.Z`, `fiberx/vX.Y.Z`, etc. (see `make tag-all`).

## Architecture

### The Context contract

`httpx.Context` (in `context.go`) is a composite of four sub-interfaces — `Request` (info + body + form), `Responder`, `Binder`, and `StateStore` — plus `Context()`/`SetContext()` for the standard `context.Context`. It has **no `Next()`**: that went with the Next-driven middleware form in v0.0.5, since a `Middleware` is handed the rest of the chain and calls it. A comment in `context.go` records the absence so it is not re-added. The doc comments on each sub-interface define **side-effect contracts** (e.g. `RequestInfo` methods must not consume the body; `BodyAccess`/`FormAccess` may). When adding methods, preserve these guarantees in every adapter or conformance will diverge.

`BodyRaw` returns a slice the **caller owns**: it must stay valid and unchanged after the handler returns. The fasthttp-based adapters therefore copy out of the pooled request buffer (`bytes.Clone`), which costs one allocation the size of the body — 1 MiB body: fiberx 606ns → 123µs, hertzx 20µs → 113µs. `BodyReader` and the native context are the zero-copy paths. This class of bug is invisible to the shared suite (every in-process requester builds a fresh native context per request, so nothing is ever reused); the deterministic cases live in `conformance/body_ownership_conformance_test.go`, which drives fasthttp/hertz context reuse directly.

`StateStore.Set/Get` is **not** propagated through `Context.Context()`. To pass values into downstream goroutines/RPC, middleware must call `SetContext(context.WithValue(...))`. Document this when touching state plumbing.

`Bind*` **decodes and does not validate** (removed in v0.0.5; every adapter used to run go-playground/validator over the `binding` tag after a successful decode). A `binding` tag means nothing to httpx; validation belongs above the transport — `protoc-gen-sphere` emits `protovalidate.Validate(&in)`, and a caller who wants something else writes it. The old contract could not hold for multi-source binding, which is the shape generated code uses: a DTO whose `json:"name"` field comes from the body and whose `uri:"id" binding:"required"` field comes from the path, bound by the sequence `BindJSON` → `BindHeader` → `BindQuery` → `BindURI`, made all five adapters return 400 at `BindJSON` — validating a `uri` field nothing had populated yet. A *decode* failure is still 400 via `WrapBindError`. Pinned by `Contract/BindIgnoresBindingTag` and `Contract/BindMultiSourceSequence`. ginx is the one adapter that cannot simply stop validating: it binds through gin's `binding` package, which validates inside every call via the process-wide `binding.Validator` variable — assigning to that would disable validation for every other gin user in the same binary, so ginx lets gin validate and drops the verdict (`decodeError` in `ginx/context.go`), which is also why `ginx` keeps a direct `go-playground/validator` dependency and the other four dropped theirs. Each adapter also has `WithTrustedProxies(...)` for a uniform ClientIP trusted-proxy policy (empty list = ignore forwarding headers; the uniform contract is pinned by `TestTrustedProxiesConformance` and the framework-specific edges — blank entries, bracketed IPv6, X-Real-IP fallback, no-option defaults — by `TestClientIPFrameworkDifferences`, both in `conformance/contract_conformance_test.go` and each documented on the adapter's own `WithTrustedProxies`), `WithAddr(addr)` for the listen address (`WithServerAddr` was removed from ginx/echox in v0.0.5; `WithAddr` absorbed its lazy `*http.Server` creation), `AdaptStdMiddleware(func(http.Handler) http.Handler) httpx.Middleware` to mount plain net/http middleware (request mutation, writer wrapping, and short-circuiting all propagate; it is the one `Adapt*Middleware` that survives the collapse to one form, because `func(http.Handler) http.Handler` is framework-neutral and maps straight onto `func(next Handler) Handler`), and `From<Framework>` (`FromGin`, `FromEcho`, `FromFiber`, `FromHertz`, `FromStd`) to build an `httpx.Context` from a native one. `FromFiber` takes the `fiber.Ctx` interface and returns `httpx.Context`: the generic `fiberContext[T]` exists only so `*fiber.DefaultCtx` fits in an interface without a heap wrapper, and the two instantiations that exist are the two the package asserts against `httpx.Context`. `FromStd` builds a standalone, unpooled context with no Engine — so `FullPath`/`Param` are empty and `ClientIP` falls back to the peer address, since there is no configured trusted-proxy policy to consult. Wildcard registration is validated by `httpx.ValidateWildcardPath` — one named wildcard, final segment — and panics uniformly otherwise.

**The promised route grammar is three shapes**, and `stdx` is the reference implementation: a static segment, a `:name` parameter filling exactly one segment, and one `*name` wildcard as the final segment — precisely what the hand-written tree in `stdx/mux.go` accepts. Anything outside it gets **no restriction and no promise**, and the second half of that is as deliberate as the first: do not add a route validator, a `RouterFeature`, or a registration-time panic for a shape that registers today. The case that forces the decision is the `google.api.http` custom-method suffix — a literal colon inside a segment, `/v1/reports:generate`, which `protoc-gen-sphere` emits. stdx matches it literally; the four framework routers read `:generate` as a parameter, so `/v1/reportsXYZ` matches too. Two such routes under one prefix panic at registration on ginx/hertzx and register silently on echox/fiberx, after which every path under the prefix reaches the last one (echo) or the first (fiber). A colon after a parameter (`/v1/users/:id:activate`) panics on ginx/hertzx, yields one parameter keyed `id:activate` on echox and stdx, and splits into two nonsense parameters on fiberx. A colon after a wildcard passes `ValidateWildcardPath` and `WildcardParamName` returns `path:archive`. Uniformity here is not reachable without giving something up that is worth more: promising one answer would mean either rejecting shapes stdx routes correctly or building per-framework escaping for a form two of the five routers cannot express at all. So the contract states the grammar and stops — documented on `httpx.Registrar`, scoped on `ValidateWildcardPath`, and covered by no conformance case, because a test over these shapes would be pinning an accident.

**A committed response follows net/http, exactly.** Once a body-writing `Responder` method has sent the header, the status and the response headers freeze and later body writes append: a later `Status`, the code a later write passes, a later `SetHeader`/`SetCookie` and the `Content-Type` a later write would have set are all dropped, whatever bytes the call produces are added to what is already there, and none of it is reported as an error. That was measured against a handler writing to an `http.ResponseWriter` rather than inferred — the standard library ignores a superfluous `WriteHeader` (and logs it), drops a `Header().Set` after the header is out, and returns `(n, nil)` from every later `Write`. ginx, echox and stdx inherit the whole rule from the writer they write through and were already right. fiberx and hertzx buffer status, headers and body until the handler returns, so nothing was frozen at all: a handler that answered 200 and then wrote a 500 error body sent 500 on both, and fiber threw the first body away as well. Both now apply the rule in **one** place — `writeBody` in `fiberx/context.go` and `hertzx/context.go` — which snapshots the header block, empties the body so the call's own bytes can be told apart from what was already sent, runs the call, then puts the snapshot back over whatever it set and concatenates. The buffer is the only seam either framework offers; there is no writer to wrap, which is why the rule cannot live in the router or in each `Responder` method. `Status`/`SetHeader`/`SetCookie` produce no body and carry their own one-line guard instead. `Body` materializes a body stream the call installed, so `DataFromReader` appends like any other write, and both frameworks recompute `Content-Length` from the body as they serialize, so the restored one cannot go stale.

`ResponseInfo.Committed()` is that predicate — has the response header been written — and it is the one thing here beyond net/http, which exposes no such accessor on `http.ResponseWriter`. It exists because nothing else can report the fact: a post-commit write succeeds silently, so `sphere/server/httpz.WithRecover` could not tell a handler that failed before writing from one that panicked after, and appended a second JSON document to a response already on its way out. ginx reads `gin.ResponseWriter.Written()`, echox `Response.Committed`, stdx its own `responseWriter.written`; fiberx and hertzx have no framework flag to read, so it is `responseDecided`/`hertzResponseCommitted`, the same predicate their routers already consult before letting the error handler render over a response. `Status(code)` alone does **not** commit on any adapter — it records the code the first write will send — while every body-writing method does, including one whose body is empty. Pinned by `httpxtest`'s `Commit` group on all five adapters and on the caller-built fiber engine, and **no `Caps` field**: the point is that the five agree. Adding a method to `ResponseInfo` breaks any third-party adapter implementing `httpx.Context`, so it needs a root-module minor bump with all five adapters tagged together.

`ResponseInfo` (`StatusCode`, `Committed`) is part of the `Context` interface — read it off `ctx` directly (the `httpx.AsResponseInfo` shim was removed in v0.0.5; it had been a no-op `return ctx, true` since `ResponseInfo` was folded into `Context`). Optional capabilities are exposed as separate interfaces probed via type assertion:
- `NativeContextProvider` → `httpx.AsNativeContext[T](ctx)` (escape hatch to the underlying `*gin.Context`, `fiber.Ctx`, etc.)
- `StdHandlerMounter` → `httpx.MountStd(r, method, path, h)` mounts a plain `net/http` handler
- `TestRequester` → `httpx.AsTestRequester(engine)` serves a request in-process for tests
- `Flusher` → `httpx.AsFlusher(ctx)` flushes buffered response data mid-handler (ginx/echox/hertzx/stdx; fiberx cannot and does not implement it). A writer that cannot flush is a **no-op, not an error**, on every adapter: that is what the interface doc promises, what gin and `httputil.ReverseProxy` do, and what a stream mounted inside `http.TimeoutHandler` (whose writer has no `Flush` and no `Unwrap`) needs — stdx used to return `ErrNotSupported` from the first flush and abandon the `Stream` callback after committing the headers, answering SSE with an empty 200, and echox returned it from `Flush()`. Pinned by `httpxtest`'s `Stream/StreamThroughNonFlushingWriter` (a bare writer through `AdaptStdMiddleware`) and `stdx/stream_test.go`. The conformance `benchmarkResponseWriter` implements `Flush` for the same reason: without it the SSE benchmark row measured a per-write `ErrNotSupported` allocation no live connection pays, and on stdx measured a stream that never ran.
- `Streamer` → `httpx.AsStreamer(ctx)` incremental streaming/SSE on all four adapters (on fiberx the callback runs after the handler returns). `httpx.ServerSentEvents(ctx, fn)` is the SSE layer on top: it sets `Cache-Control: no-cache` / `X-Accel-Buffering: no`, commits a 200 `text/event-stream` response, and hands fn an `*httpx.SSEWriter` (`Send`/`SendData`/`SendJSON`/`Comment`) that encodes WHATWG event-stream framing in `sse.go` and flushes one event per write.
- `RouterFeatureProvider.SupportsRouterFeature(...)` → currently only `RouterFeatureNamedWildcard`. Adapters without named wildcards (echox, fiberx) normalize `/*filepath` internally at registration time and keep `Param("filepath")` working; `FixWildcardPathIfNeed`/`WildcardParamName` are the shared helpers behind this.

### Errors

`httpx.Error` composes `StatusError + CodeError + MessageError`. The concrete type is unexported on purpose — return the `Error` interface from constructors. `ParseError(err)` extracts those fields and returns an **empty** message when the error carries none — it is the default `ErrorParser` in `sphere/httpz`, so its message reaches a response body and must never be `err.Error()`. Anything that renders should call `RenderError` / `ClassifyError` instead, which substitute `http.StatusText(status)` (status + `{success, code, message}`, no raw `err.Error()`); that is what the adapter default error handlers use. `NewXxxError(msg)` puts `msg` in `GetMessage()`; `XxxError(err)` without extra arguments does not. Bind failures should go through `WrapBindError`.

`httpx.ErrorHandler` (`func(Context, error)`) is the framework-neutral error handler. **All five adapters accept it under one name, `WithErrorHandler`** (unified in v0.0.5; ginx/hertzx previously spelled it `WithHTTPXErrorHandler` and gave `WithErrorHandler` to their native shape), and invoke it with a real adapter-backed `httpx.Context`. On ginx and hertzx the wrapper also aborts the native context afterwards unless the handler already did, so the rest of the chain cannot write over the error body. The two adapters whose framework has an error-handler shape of its own keep it under `WithNativeErrorHandler` (`ginx.ErrorHandler`, `hertzx.ErrorHandler`); echox/fiberx/stdx have no such option because their `WithErrorHandler` already covers every error they render. Each adapter also exports `DefaultErrorHandler` — the naming rule is **this adapter's default handler in its native shape**, the value it installs on the framework when nothing is configured, which is why the five signatures differ and why for stdx the native shape simply *is* `httpx.ErrorHandler` (net/http has no error handler to match). Never assume `DefaultErrorHandler` is interchangeable across adapters; `WithErrorHandler` is the portable surface. The echox/fiberx defaults understand `*echo.HTTPError`/`*fiber.Error` so framework 404s keep their status. A committed response is never overwritten by an error body on any adapter — and the error is not lost either: it travels out of the composed chain as an ordinary return value, so an outer layer's `next(ctx)` returns it and logging and metrics see a handler that failed after writing its response. That used to need per-adapter plumbing, because a `Use` layer sat on the far side of a native handler boundary (gin/hertz appended to the native error list, echo returned it to echo's error path, fiberx parked it on the context under an unexported Locals key); with one composed chain per route the whole chain is on this side of that boundary and the fiberx Locals lookup — ~4-6ns per `Use` layer — is gone. Pinned by `Regression/OuterLayerSeesErrorAfterCommittedResponse`.

Every adapter defaults its `httpx.ErrorHandler` so httpx errors are rendered by the adapter, not by the framework's own handler. That matters for the one configuration an adapter cannot fix up afterwards: `fiber.Config` is immutable after `fiber.New`, so an engine passed through `fiberx.WithEngine` keeps the caller's `ErrorHandler` (fiber's plain-text default, which leaks `err.Error()` and reports every status as 500) and the caller's `UnescapePath` (off by default, which leaves route parameters percent-encoded). `fiberContext.paramValue`/`bindURI` decode when that flag is off — both gated so an ordinary request pays only a byte scan. The whole suite runs a second time against a caller-built `fiber.App` (`fiberxOwnEngineSuite` in `conformance/httpxtest_suite_test.go`), which is how both defects surfaced; add to it rather than trusting that a constructor-built engine represents every deployment.

### Adapter pattern

Each adapter follows the same shape: `engine.go` (Config/Option/New/Start/Stop/IsRunning), `router.go` (RouterGroup wrapper with `toXxxHandler` that calls the framework handler and routes errors through the adapter's `ErrorHandler`), `context.go` (concrete `Context` impl), `std_middleware.go` (`AdaptStdMiddleware`, and any writer bridging it needs), and where the native binder is insufficient, a `uri_binding.go` / `binding.go`.

`JSON` renders through the **framework's own encoder**, never `encoding/json` directly: ginx goes through `gin/codec/json.API` and hertzx through hertz's `render.JSONRender`, so a caller who configured a custom codec on the framework gets it here too. An encoding failure returns the error without committing a response, and 1xx/204/304 write no body. `StateStore` is per-request and must not be guarded by a package-level lock — fiberx's `Set/Get` used to take one, which serialized unrelated requests; the contract is that different requests never block each other, while two goroutines inside one request are the caller's problem (native `Locals` is not protected either).

Four of the five join a group prefix onto a route path with `path.Join` (their own `joinPaths`, which keeps a trailing slash the caller wrote so `BasePath()` gives back what was written). **echo joins by plain string concatenation** — `Group.Add` registers `g.prefix+path` and `Group.Group` registers `g.prefix+prefix` — so echox must never hand echo a caller's prefix directly. `echoScopePrefix`/`echoGroupPrefix`/`echoRoutePath` in `echox/router.go` derive what echo gets from the `joinPaths`-maintained `basePath` instead, on the invariant that an echo group's prefix is always `basePath` minus its trailing slash. Without that, `Group("/")` + `GET("/x")` registered `//x` and 404'd, and `Group("/api/")` + `GET("")` registered `/api` where the other four register `/api/`; `BasePath()` reported the right thing in both cases, so it was silent. Fixed in v0.0.5 and pinned by `httpxtest`'s `GroupPrefix` group.

`UseNative(...native middleware)` is on both `Engine` and `Router` in ginx (`gin.HandlerFunc`), echox (`echo.MiddlewareFunc`), fiberx (`fiber.Handler`) and hertzx (`app.HandlerFunc`): it hands the layer to the framework's own chain with no adapter in between, and as of v0.0.5 it is the **only** way to mount one. `AdaptGinMiddleware`/`AdaptEchoMiddleware`/`AdaptFiberMiddleware`/`AdaptHertzMiddleware` were removed and cannot come back in the composed form: all of a scope's httpx layers share one native handler slot, so a native middleware's own continuation (gin's `c.Next`, hertz's `ctx.Next`, fiber's `c.Next`, the `echo.HandlerFunc` echo hands a `MiddlewareFunc`) would advance the framework past that slot instead of into the layer below. Because every adapter now composes `Use` into the route, one rule that used to be fiberx-only holds everywhere: a `UseNative` layer always runs *outside* everything `Use` registered on the same scope, whatever the call order. Pinned by `ginx/middleware_test.go`, `echox/naming_test.go`, `fiberx/naming_test.go`, `hertzx/naming_test.go` and `httpxtest`'s `Chain/NativeMiddlewareWrapsLayers`. One fiberx-only rule remains: register `UseNative` **before** the routes it should wrap, because fiber matches its stack in registration order. **stdx deliberately has no `UseNative`**: there is no framework chain to hand a middleware to and net/http has no middleware type but the one `AdaptStdMiddleware` already takes, so the only possible body would be `Use(AdaptStdMiddleware(mw))` — and `AdaptStdMiddleware` there is not a bridge but the implementation, the thing that carries the rest of the composed chain across the net/http handler boundary and follows a replaced request or wrapped writer. Adding the name would advertise a shorter path that does not exist; the reasoning is recorded on `stdx.AdaptStdMiddleware` itself.

`middleware.go` (root) holds the **one** middleware form, as of v0.0.5: `Middleware = func(next Handler) Handler`, `MiddlewareScope` (`Use(...Middleware)`) — which both `Router` and `Engine` embed, so a caller holding either interface calls the method — `ComposeMiddleware`, and the two adapter-facing types `MiddlewareChain`/`MiddlewareFallback`. It replaced `interceptor.go`: `Middleware` *is* that file's `Interceptor`, renamed. Gone with the Next-driven `func(Context) error`: the name `Interceptor`, `InterceptorScope`, the free `UseInterceptor`, `AsMiddleware`, `AsInterceptor`, `Context.Next()`, and the `nextContext`/`preserveCapabilities` bridging that existed only to convert between the two forms. `Router.Group`/`Engine.Group`'s variadic is `...Middleware`. Each adapter's `Router`/`Engine` holds an `*httpx.MiddlewareChain` and composes it into each route inside `toGinHandler`/`toEchoHandler`/`adaptHandler`/`toHertzHandler`/`Handle`, so a chain holds no per-request state at all (0 allocations, one call per layer, no depth cliff). Consequences that are part of the contract and are pinned by `ginx/middleware_test.go`, `ginx/middleware_alloc_test.go`, `stdx/router_test.go` and `httpxtest`'s `Chain` and `MiddlewareScope` groups: layers always run inside anything registered through `UseNative` on the same scope whatever the call order, and an inner error is rendered at the route — not at the failing layer. Returning without calling `next` is how a layer stops the chain (no Abort bookkeeping, no layer index, no second-`Next` hazard).

Two rules about *when* a chain is resolved and *what* it covers, both encoded in `MiddlewareChain` so they are written once rather than five times:

- **Resolved per route at registration, not per scope at creation.** A `Group` keeps a reference to its parent's chain, so `engine.Use(B)` after `g := engine.Group(...)` still reaches the routes `g` registers afterwards; before v0.0.5 `Group` copied the slice and `B` silently reached nothing. Routes already registered keep the chain they were registered with — that is gin's rule for its own `Use` and what makes a registered route immutable. The reference costs one pointer hop per route registration and nothing per request. This is uniform across all five now: the pre-v0.0.5 asymmetry (late `engine.Use` reached an existing group on echox/fiberx and not on ginx/hertzx/stdx, because those copied at `Group` time) is gone with the per-framework `Use` registration it came from.
- **Registered routes plus, for the engine scope only, unmatched paths.** `Static`/`StaticFS`/`HandleStd` register through `Handle` and therefore *are* inside middleware chains: all five adapters serve static mounts with the shared `httpx.StaticFileHandler` (net/http `FileServer` + `StripPrefix`, 404 for a directory or the bare prefix) wrapped in an adapter-local `stdLeaf` that serves a plain `http.Handler` from the native context. An engine-scope chain also covers 404/405, which is what it took for the composed form to be usable for an access log or panic recovery at all — and therefore what made collapsing the two forms into one possible. A **group's** chain must not: a 404 belongs to no group. The composition cannot be snapshotted where the fallback is installed (`installRouteFallback` runs inside `New`, before any `Use` call) and must not be rebuilt per request (one closure per layer on the cheapest request there is to send), so `httpx.MiddlewareFallback` caches it against the chain's current layer-list pointer and rebuilds only after a registration. A 404 on ginx costs 7 allocations with no middleware and 7 with eight, pinned by `ginx/middleware_alloc_test.go`. The assumption is the usual one — registration finishes before serving starts; a `Use` racing a request is race-free (the layer list is replaced, never mutated) and the request simply sees the old chain or the new one. Where each adapter hooks the fallback differs because the frameworks differ: gin/hertz `NoRoute`/`NoMethod`, stdx's own no-match branch in `ServeHTTP`, echox's `Echo.HTTPErrorHandler` (gated on `errors.Is(err, echo.ErrNotFound/ErrMethodNotAllowed)` — identity, so a route returning its own 404 is not mistaken for an unmatched path), fiberx the `routeFallback` layer registered ahead of every route, which sees `fiber.ErrNotFound`/`ErrMethodNotAllowed` come back out of `ctx.Next()`. The old `Caps.InterceptsUnmatchedPathInsideUse` — which recorded whether the composed chain sat inside or after engine-scope `Use` middleware on an unmatched path — is gone with the distinction: `Use` *is* the chain now, so there is nothing for it to sit inside or after. A path no route accepted the request for — 404 or 405 — has **no** `FullPath()` to report, whatever the framework leaves lying around: gin/hertz/stdx never set one, while fiberx had fiber's `Use` route (registered at `/`) answering for every unmatched path and echox had echo's 405 leaving the path-matching node's registered path on the context, so both reported a pattern no route had handled. A layer keyed on `FullPath` — `httpz.MatchOperation` authorization, rate limiting — cannot tell "no route" from "the route you named" otherwise; pinned by `httpxtest`'s `Selector` group.

When adding behavior, **change the root interface first, then implement it in all four adapters, then add a conformance test**. Response shape is pinned by golden contracts (`conformance/golden_test.go`, files in `conformance/testdata/golden/`): `assertMatchesGolden` renders status / Content-Type / `Location` / `X-Trace` / `Set-Cookie` / body (JSON canonicalized) into one text snapshot, requires **all four** adapters to agree, and compares the agreed value against the recorded file. Regenerate with `go test ./conformance -run TestXxx -update-golden`; update mode refuses to write while adapters disagree, so a golden file is a four-way consensus, never a recording of ginx. This replaced an older `assertMatchesGin` helper that defined correctness as "equal to whatever ginx produced" — that hid two classes of defect: a wrong ginx behavior, and a change in the shared root package (`RenderError`, `WrapBindError`, the JSON envelope) moving all four responses at once. Content-Type is part of the contract only where the body is (see the rule in `contractOf`); everything that is *not* response shape — middleware order, abort, allocation counts, lifecycle, streaming timing — stays as inline assertions, because a golden file for a control-flow sequence invites `-update-golden` to accept a reordering bug. If an adapter's behavior is itself wrong, fix that adapter — don't loosen the contract.

### Engine lifecycle

`Engine.Start()` blocks; `Stop(ctx)` triggers graceful shutdown; `IsRunning()` is backed by `atomic.Bool`. Engines are **single-use**: Start after Stop (in either order) returns `httpx.ErrEngineClosed` on every adapter — construct a new Engine to serve again. ginx/echox bind the listener before setting the running flag. The root package also provides `Start`/`Close` for driving a plain `*http.Server` (`http.ErrServerClosed` swallowed on the way in, `Shutdown` on the way out).
