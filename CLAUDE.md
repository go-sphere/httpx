# CLAUDE.md

Guidance for agents working in this repository. History and measurements live
in commits, `CHANGELOG.md` and `benchmarks/`; this file states current rules.

## Repository layout

A Go workspace of seven modules, each with its own `go.mod`:

- `.` (`github.com/go-sphere/httpx`): framework-agnostic interfaces (`Context`,
  `Engine`, `Router`, `Binder`, `Responder`, `Error`) and shared helpers. **No
  third-party dependencies**; keep it that way. Also contains:
  - `httpxtest/`: the shared conformance suite every adapter runs
    (`httpxtest.Run`), with golden response contracts in `httpxtest/golden/`.
  - `httpxmock/`: an in-memory `httpx.Context` for unit-testing handlers and
    middleware. Every method has a real body (no embedded interface); `Bind*`
    return `ErrBindUnsupported`.
- `ginx/`, `echox/`, `fiberx/`, `hertzx/`: adapters over Gin, Echo v4, Fiber v3
  and Hertz.
- `stdx/`: adapter over plain `net/http`, with its own router (`stdx/mux.go`).
  It is the reference implementation of the route grammar.
- `conformance/`: what cannot live in `httpxtest`: cross-framework benchmarks,
  tests needing a real listener (trusted proxies, stream delivery, FD leaks),
  lifecycle, stress, and native-context-type assertions. Uses `replace` to the
  local adapters.
- `benchmarks/`: `BENCHMARK.md` is generated by `make bench-report`; never
  edit it by hand. Nothing under `benchmarks/results/` or `benchmarks/bin/` is
  tracked, because `benchmarks/` ships in the root module zip.

`go.work` is gitignored; `make work` creates it (CI does too). Adapter `go.mod`
files must **not** contain `replace`. Tags are per module (`ginx/vX.Y.Z`, ...);
adding a method to a root interface breaks third-party adapters, so it needs a
root minor bump with all adapters tagged together.

## Commands

```bash
make work          # create/refresh go.work
make build         # compile all modules (CI)
make test          # test all modules (CI)
make tidy-check    # module hygiene, GOWORK=off (CI)
make lint          # fmt check, vet, golangci-lint, nilaway
make check         # tidy-check + lint + race tests (local gate)
make bench-report  # regenerate benchmarks/BENCHMARK.md
go test ./conformance/ -run TestEngineConformance/ginx -v
HTTPX_UPDATE_GOLDEN=1 go test ./conformance/ -run <Test>   # rewrite goldens
```

`make tag`, `make tag-all` and `make tag-delete` push or delete remote tags;
run them only when asked.

## How to change behaviour

1. Change the root interface or helper first.
2. Implement it in **all five** adapters.
3. Add a case to `httpxtest` so every adapter (and the caller-built fiber
   engine, `fiberxOwnEngineSuite`) is held to it. Do not add a test to just
   one adapter for shared behaviour.

Golden files are a consensus: update mode refuses to write while adapters
disagree. Goldens cover response shape only; control flow (middleware order,
allocations, lifecycle, streaming timing) is asserted inline. If one adapter is
wrong, fix the adapter; do not loosen the contract.

## Contracts

### Context

`httpx.Context` = `Request` + `Responder` + `Binder` + `StateStore` +
`Context()`/`SetContext()`. It has **no `Next()`**; middleware receives `next`.
Each sub-interface's godoc defines side-effect rules (e.g. `RequestInfo` must
not consume the body); keep them in every adapter.

- `BodyRaw` returns a slice the caller owns. fasthttp-based adapters copy it
  (`conformance/body_ownership_conformance_test.go` covers context reuse).
  `BodyReader` and the native context are the zero-copy paths.
- `StateStore` values do **not** propagate through `Context()`; use
  `SetContext(context.WithValue(...))` for values that must cross into
  goroutines or a mounted net/http handler. `StateStore` is per request: never
  guard it with a package-level lock.
- `Bind*` **decode only and never validate**; a `binding` tag means nothing to
  httpx. Validation belongs above the transport (`protoc-gen-sphere` emits
  `protovalidate.Validate`). Decode failures go through `WrapBindError` (400; 413 for a
  `*http.MaxBytesError`).
  ginx lets gin validate (gin's validator is process-wide) and discards the
  verdict in `decodeError`.

### Route grammar

Promised shapes: static segments, `:name` filling one segment, and one `*name`
wildcard as the final segment (`httpx.ValidateWildcardPath` panics otherwise).
Anything else, e.g. a custom-method suffix like `/v1/reports:generate`, has
**no restriction and no promise**: the frameworks disagree and cannot be made
to agree. Do not add a validator, a `RouterFeature`, a registration panic, or a
conformance case for such shapes.

Matching follows `stdx`: a path matches exactly as received after decoding
(case sensitive, a literal `+` stays `+`, and a trailing-slash variant never
reaches the route; gin and hertz redirect it, the others 404), a static
segment beats a parameter and a parameter beats a wildcard regardless of
registration order, and a GET route does not answer HEAD (405 without HEAD in
`Allow`). fiberx gets this from its `NewConfig` defaults (`CaseSensitive`,
`StrictRouting`, `DisableHeadAutoRegister`), `keepLiteralPlus` and
`routeOrder`; an app passed through `fiberx.WithEngine` keeps its own config.

Adapters without named wildcards (echox, fiberx) normalize `/*name` at
registration so `Param(name)` works (`FixWildcardPathIfNeed`,
`WildcardParamName`).

### Responses

A committed response follows net/http exactly. Once a body-writing `Responder`
method sends the header, status and headers freeze: a later `Status`,
`SetHeader`, `SetCookie` or Content-Type is dropped, later body bytes append,
and none of it is an error. `Status` alone does not commit; every body-writing
method does, even with an empty body.

- ginx, echox and stdx inherit this from their `http.ResponseWriter`. fiberx and
  hertzx buffer the response, so they apply the rule in one place, `writeBody`
  in their `context.go`.
- `Committed()` reports whether the header has been written. There is no
  `Caps` flag for it; all five must agree.
- `JSON` uses the **framework's encoder** (gin codec, hertz render), never
  `encoding/json` directly. An encode error commits nothing; 1xx/204/304 write
  no body.

Optional capabilities are separate interfaces probed by helpers:
`AsNativeContext[T]`, `MountStd`, `AsTestRequester`, `AsFlusher` (a writer that
cannot flush is a no-op, never an error; fiberx has no flusher), `AsStreamer`
(on fiberx the callback runs after the handler returns, outside middleware;
behind `AdaptStdMiddleware` the stream is passed through, not replayed),
`AsResponseHeaderEditor` (append to and read response headers), and
`RouterFeatureProvider`. `ServerSentEvents` (`sse.go`) builds SSE on
`Streamer`. `File` serves regular files only: every adapter calls
`httpx.CheckServeFile` first, so a directory or missing path is a 404 error.

### Errors

- `httpx.Error` = `StatusError` + `CodeError` + `MessageError`; the concrete type
  is unexported, so constructors return the interface.
- `ParseError` returns an empty message when the error has none. It is the
  default parser in `sphere/httpz`, so it must never fall back to `err.Error()`.
  Code that renders an error calls `RenderError` or `ClassifyError`, which
  substitute `http.StatusText`.
- All five adapters take `WithErrorHandler(httpx.ErrorHandler)`; that is the
  portable option. ginx and hertzx keep their framework's shape under
  `WithNativeErrorHandler`.
- Each adapter's `DefaultErrorHandler` is in its native shape, so the five are
  not interchangeable.
- A committed response is never overwritten by an error body. The error still
  returns up the chain, so outer layers see it.
- `fiber.Config` is immutable after `fiber.New`. An engine passed through
  `fiberx.WithEngine` keeps the caller's `ErrorHandler` and `UnescapePath`, so
  fiberx decodes params itself when `UnescapePath` is off.

### Middleware

One form: `Middleware = func(next Handler) Handler`, registered with `Use` on
`Router`/`Engine` and composed into each route at registration
(`MiddlewareChain`). A layer stops the chain by not calling `next`; an inner
error is rendered at the route, not at the failing layer.

- A `Group` references its parent chain, so a later `engine.Use` reaches routes
  the group registers afterwards. Routes already registered keep their chain.
- An engine-scope chain also covers unmatched paths (404/405), through
  `MiddlewareFallback`. A group chain never does. Unmatched paths report an
  empty `FullPath()`.
- `Static`/`StaticFS`/`HandleStd` register through `Handle`, so middleware
  covers them.
- `UseNative` (ginx, echox, fiberx, hertzx) hands a framework middleware to the
  framework chain. It always runs outside the `Use` layers on the same scope.
  On fiberx, register it before the routes it should wrap; a route whose
  precedence would move it across one panics.
- stdx has **no `UseNative`**: its `AdaptStdMiddleware` is the native form.
- `AdaptStdMiddleware` mounts `func(http.Handler) http.Handler` on every
  adapter. Do not reintroduce `AdaptGinMiddleware`-style bridges: a native
  continuation would skip the composed layers.

### Adapter shape

Each adapter has:

- `engine.go`: Config, Option, New, Start, Stop, IsRunning.
- `router.go`: the router wrapper, composing middleware and routing errors to
  the error handler.
- `context.go`: the `Context` implementation.
- `std_middleware.go`.
- A binding file where the native binder falls short.

Shared options:

- `WithAddr`.
- `WithTrustedProxies`: an empty list ignores forwarding headers.
- `WithErrorHandler`.
- `WithMaxBodySize(n)`: checked per route before the httpx chain runs
  (`httpx.LimitRequestBody` on net/http, buffered length on fiber/hertz); an
  oversized body is a `*http.MaxBytesError`, which classifies as 413.
- `From<Framework>` builds a `Context` from a native one. `FromStd` has no
  engine, so `FullPath` and `Param` are empty.

echo joins group prefixes by string concatenation, so echox derives echo's
prefixes from its own `basePath` (`echoScopePrefix`, `echoGroupPrefix`,
`echoRoutePath`) and never passes a caller's prefix to echo directly.

### Engine lifecycle

- `Start` blocks, `Stop(ctx)` shuts down gracefully, and `IsRunning` is an
  atomic flag.
- Engines are single-use: `Start` after `Stop` returns `httpx.ErrEngineClosed`.
- `Stop` before `Start` returns nil, and `Start` returns nil once `Stop` has
  ended it.
- The root `Start`/`Close` helpers drive a plain `*http.Server`.
