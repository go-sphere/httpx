# Archived reports

Two reports are kept here. Neither is a baseline — the current baseline is
[../BENCHMARK.md](../BENCHMARK.md), and it is regenerated whenever anyone runs
`make bench-report`.

| Report | What it records |
| --- | --- |
| [GIN_DEPTH_REPORT.md](GIN_DEPTH_REPORT.md) | Why cost jumps at a certain middleware depth on gin: the control experiments that attributed it to stack growth, and why PGO was evaluated and not adopted as a default. |
| [MIDDLEWARE_FUSION_REPORT.md](MIDDLEWARE_FUSION_REPORT.md) | The chain-fusion approach — prototype, measurements, semantic validation, the version that shipped, and **why it was then removed**. |

They survive for one reason: they record *why the code looks the way it does*. Which approach
was tried, what it actually bought, and what made it unacceptable — none of that can be
regenerated by re-running a benchmark, because the code being measured no longer exists.

Five other reports were deleted once `BENCHMARK.md` covered them. `CURRENT_REPORT.md`,
`SCENARIO_REPORT.md` and `SCENARIO_NATIVE_REPORT.md` measured exactly what sections 1–4 now
measure, for four frameworks instead of five, and two of them were built around `Interceptor`,
a type removed in v0.0.5. `REPORT.md` and `WRAPPER_REPORT.md` were before/after snapshots of
optimizations that have since shipped; the decisions they justify are recorded in `CLAUDE.md`
(the per-adapter JSON encoder, the per-request state store with no package-level lock, and why
`Context` is not pooled), which is where someone changing that code will actually look.

**Do not quote numbers from here next to `BENCHMARK.md`, or next to each other.** Each was
measured on its own: a different commit, different sampling, a different compiled binary.
`BENCHMARK.md` is internally comparable only because the whole file comes from one run.

Both reports name the raw sample files they were built from, under the `fusion-*` and
`gin-depth-*` prefixes, but **those files are not in the repository**. `benchmarks/` is part of
the root Go module, so anything tracked here would ship in the module zip every consumer of
`github.com/go-sphere/httpx` downloads. The tables inside each report are the record.
